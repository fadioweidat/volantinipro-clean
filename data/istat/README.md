# ISTAT Data Import for VolantiniPro

This directory manages the official territorial and demographic import used by Step 2.

## Scope

The default production scope is Lombardia-first. Use `npm run import:istat:italy` for the all-Italy path after all source files are available.

Validation municipalities are samples only. They are never manually seeded as production data.

## Folder Structure

- `downloads/`: Raw official source files downloaded from ISTAT or other institutional providers.
- `raw/`: Extracted shapefiles and intermediate source data.
- `processed/`: Normalized JSON files and import reports generated by the pipeline.

## Required Source Files

Place the official files in `data/istat/downloads` before running the import.

1. **ISTAT administrative boundaries**
   - Source page: https://www.istat.it/notizia/confini-delle-unita-amministrative-a-fini-statistici-al-1-gennaio-2018-2/
   - Current reference found on 2026-05-13: "Confini amministrativi 2026", generalized or non-generalized ZIP.
   - Purpose: municipality codes, names, province/region fields, cadastral code when present, area, centroid, PostGIS geometry.

2. **ISTAT municipal demographic data**
   - Source page: https://www.istat.it/classificazione/codici-dei-comuni-delle-province-e-delle-regioni/
   - Current reference found on 2026-05-13: "Bilancio annuale demografia comunale - anni 1991-2025".
   - Purpose: population, households/famiglie, and demographic fields when available in the workbook/CSV.

3. **Optional supporting sources**
   - MEF/OMI or other institutional economic files for `average_income`.
   - OpenStreetMap/Overpass, Google Places, Foursquare, and GTFS are consumed by Edge Functions, not by this ISTAT importer.
   - Economic indicators can be imported separately with `npm run import:economic` when official files are present in `data/istat/downloads`.

Fields not present in the official source files are imported as `null`; the pipeline does not invent values.

## Commands

```bash
npm run import:istat:dry-run
npm run import:istat
npm run import:istat:italy
npm run import:economic:dry-run
npm run import:economic
```

The import:

- extracts ZIP files from `downloads` into `raw`;
- reads ISTAT municipality shapefiles;
- normalizes rows into `processed`;
- upserts into Supabase through `public.upsert_istat_territorial_batch`;
- validates dataset status and random Lombardia examples;
- writes `processed/import_report_<scope>.json`.

If `downloads` is empty, the command fails. This is intentional so production cannot silently fall back to demo rows.
